# EdgeEver 图床迁移插件（CloudFlare ImgBed）

将 EdgeEver 笔记中的图片上传到 [CloudFlare ImgBed](https://github.com/MarSeventh/CloudFlare-ImgBed) 图床，并把笔记里的本地图片引用替换为 Markdown 外链。所有功能均可在插件设置中开关。

> **重要边界说明**：受 EdgeEver 插件 API 能力限制，本插件**无法**在图片插入/粘贴/拖拽时拦截上传流程、做到"图片不经过 EdgeEver 服务器直接进入图床"。插件能做的是：图片已成为笔记附件后，上传到图床并替换引用。详见 [未实现功能说明.md](./未实现功能说明.md)。

## 功能一览

| 功能 | 说明 | 开关 |
| :--- | :--- | :--- |
| 手动上传当前笔记图片 | 命令「上传当前笔记图片到图床」：扫描当前笔记的本地图片引用 → 上传 → 替换为 `![alt](url)` | 随时可用 |
| 管理面板 | 命令「打开图床迁移面板」：本地文件直传、笔记资源列表、单文件上传、上传记录、备份恢复 | 随时可用 |
| 保存后自动上传 | 监听 `note.updated`，笔记保存后自动上传并替换本地图片 | `保存后自动上传并替换本地图片` |
| 自动上传范围 | 仅当前编辑的笔记 / 所有发生更新的笔记 | `自动上传范围` |
| 替换后删除本地资源 | 替换成功后删除 EdgeEver 中的原资源，节省空间 | `替换成功后删除 EdgeEver 本地资源` |
| 同步删除图床文件 | 插件删除本地资源、或笔记被删除时，同步删除图床上的对应文件（需 Token 有 `delete` 权限） | `删除本地资源时同步删除图床文件` |
| 替换前备份 | 每次替换前把笔记原文存入本机存储，可一键恢复 | `替换前自动备份笔记原文` |
| 上传记录复用 | 同一资源再次处理时直接复用已生成的链接，不重复上传 | 自动 |

## 安装

### 方式一：本地调试（开发期）

1. 构建产物（或直接使用仓库中已构建的 `main.js`）：
   ```bash
   npm install
   npm run build
   ```
2. 在 EdgeEver 的「插件市场」页面输入本地 Manifest 地址，例如：
   ```text
   /extensions/edgeever-imgbed-plugin/manifest.json
   ```
   （具体路径以 EdgeEver 本地调试文档为准）

### 方式二：GitHub 分发

1. 将包含 `manifest.json`、`main.js`、`styles.css` 的仓库发布为公开 GitHub 仓库；
2. 创建 GitHub Release，Tag 与 Manifest 版本一致（如 `v1.0.0`）；
3. 在 Release 资产中上传三个文件；
4. 用户在插件市场输入仓库地址安装：
   ```text
   https://github.com/<owner>/edgeever-imgbed-plugin
   ```

## 配置

在 EdgeEver 的插件设置界面（宿主统一渲染）中配置：

| 设置项 | 说明 |
| :--- | :--- |
| 图床站点地址 | 必填。如 `https://img.example.com`，不带末尾斜杠 |
| 鉴权方式 | `API Token（Bearer）` / `上传认证码` / `无鉴权` |
| API Token | 在图床「管理界面 → 系统设置 → 安全设置 → API Token 管理」创建，至少需要 `upload` 权限；如需同步删除再加 `delete` |
| 上传认证码 | 与 Token 二选一，作用于用户端上传认证场景 |
| 返回链接格式 | `完整链接` / `/file/ 路径`（自动拼接站点地址） |
| 上传渠道 | telegram / cfr2 / s3 / discord / huggingface / webdav，默认 telegram |
| 渠道名称 | 多渠道场景下指定具体渠道 |
| 文件命名方式 | default / index / origin / short |
| 上传目录 | 图床内的相对路径，默认 `edgeever` |
| 服务端压缩 | 仅 Telegram 渠道生效 |
| 本地图片引用识别规则 | 正则。留空 = 自动识别（非 http(s)/data: 开头，或能匹配到笔记资源的引用）；填写后仅匹配该正则的引用被视为本地图片 |
| Markdown 链接模板 | 默认 `![{alt}]({url})`，可用占位符 `{alt}` `{url}` `{name}`。图片按此模板嵌入显示；**非图片附件**会自动改用链接语法（去掉模板开头的 `!`，如 `[alt](url)`），避免渲染成裂图 |
| 单文件大小上限 | 默认 20MB，`0` 表示不限制。超过上限的文件跳过并提示（未实现分块上传） |
| 同时上传非图片附件 | 默认关。开启后 PDF 等附件一并上传；附件以**链接**形式写入笔记（而非图片）。可上传的文件类型由图床决定，本质为图床、以图片最佳；非图片受渠道大小限制（如 Telegram 20MB） |

## 使用

### 命令（命令面板 / 桌面端快捷菜单）

1. **上传当前笔记图片到图床** — 处理当前打开的笔记（无编辑器时回退为最近更新的笔记）；
2. **打开图床迁移面板** — 管理界面；
3. **恢复当前笔记替换前的内容** — 从最近一次备份还原。

### 管理面板

- **本地文件直传**：选择本地文件直接传到图床，生成链接/Markdown，可复制或插入到光标。此路径确实不经过 EdgeEver 服务器（文件来自用户本机，而非笔记附件）；
- **笔记图片**：选择笔记 → 加载资源列表 → 单文件上传，或「上传并替换全部」；
- **上传记录**：历史上传的链接，支持复制与删除远端；
- **替换备份**：恢复或删除备份。

### 自动上传（事后处理）

开启「保存后自动上传并替换本地图片」后，每次笔记保存（`note.updated`）时：
- 范围为「仅当前笔记」时，只处理当前编辑器打开的笔记；
- 范围为「所有笔记」时，处理发生更新的任意笔记；
- 处理完成后引用已是外链，不会重复上传（内置防循环）。

## 本地图片引用是如何识别的

EdgeEver 未公开笔记 Markdown 中本地图片的引用语法，插件采用通用策略：

1. 扫描所有 `![alt](target)` 与 `![[target]]` 形式的图片引用；
2. 依次尝试把 `target` 匹配到笔记资源：资源 ID 出现在引用中 → 文件名精确/路径后缀相等 → 去扩展名后相等；
3. 匹配到资源 → 本地图片，上传后按模板替换；
4. 匹配不到且是 `http(s)://` 绝对地址 → 远程图片，跳过；
5. 匹配不到且是 `data:` → 内联数据，跳过；
6. 匹配不到的其他形式 → 在通知中报告「N 处引用无法匹配到笔记资源」，正文不改动。

如果实测发现 EdgeEver 的引用语法特殊，可在设置中填写「本地图片引用识别规则」正则精确指定（例如 `^edgeever://`）。

## 开发

```bash
npm install        # 安装 typescript / esbuild
npm run build      # 打包 src/index.ts → main.js（单文件 ESM，约 49KB）
npm run typecheck  # TypeScript 严格模式检查
npm test           # 冒烟测试（Mock 宿主环境，20 个用例）
```

源码结构：

```
src/
  index.ts     入口：activate 生命周期、事件监听（自动上传 / 笔记删除清理）
  commands.ts  三个全局命令
  panel.ts     管理面板（原生 DOM）
  uploader.ts  核心编排：分析 → 上传 → 写回 → 清理
  imgbed.ts    图床 API 客户端（上传 / 删除 / 连通性测试）
  markdown.ts  图片引用扫描、分类、匹配与替换
  notes.ts     笔记 / 资源 / 编辑器读写辅助
  settings.ts  设置 Schema 默认值与读取
  records.ts   上传记录（资源 ↔ 图床文件映射）
  backup.ts    替换前原文备份
  types.ts     插件 API 的最小 TypeScript 声明
test/
  mock.mjs     Mock 宿主环境
  smoke.mjs    冒烟测试
```

## 已知限制

- Android / iOS 原生端不运行插件（EdgeEver 平台限制）；
- 自动上传依赖应用处于打开状态（事件驱动，无后台调度）；
- 设置与备份仅存本机，不跨设备同步；
- 大文件分块上传未实现；
- 完整列表见 [未实现功能说明.md](./未实现功能说明.md)。
